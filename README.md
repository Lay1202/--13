# 과제 13: 병합 정렬과 퀵 정렬의 성능 비교

병합 정렬과 퀵 정렬(First / Random / Median-of-Three 피벗)을 구현해 비교 횟수, 실행시간, 메모리 사용량을 측정했습니다. 전체 실행 로그는 `merge_quick_result.txt`에 있습니다.

- 빌드: `gcc -O2 -o merge_vs_quick merge_vs_quick.c` (Visual Studio에서는 Release / x64 권장)
- 데이터: 과제 12와 같은 생성기·시드·생성 순서를 써서 같은 데이터입니다(0~1,000,000 무작위 정수, 중복 허용). 그래서 퀵 정렬의 비교 횟수가 과제 12 결과와 정확히 같습니다(예: n=1,000에서 First 10,280 / Random 10,244 / Median-3 10,583). 각 크기에서 모든 알고리즘은 같은 원본의 복사본으로 실행합니다.
- 검증: 모든 정렬 결과의 오름차순 여부와 원본과의 합·제곱합 일치를 확인했고 전부 통과했습니다.

## 1. 측정 방법

**비교 횟수:** 병합 정렬은 병합 과정에서 두 원소를 비교한 횟수를 셉니다. 퀵 정렬은 분할에서 원소와 피벗을 비교한 횟수와 Median-of-Three의 중앙값 결정 비교를 모두 셉니다. 루프 조건 검사는 세지 않습니다.

**실행시간:** 정렬 시작부터 끝까지만 `QueryPerformanceCounter`(Windows) / `clock_gettime`(Linux)로 재고, 배열 복사·데이터 생성·출력은 제외했습니다. 한 번의 정렬이 매우 짧아서 같은 원본으로 300번(워밍업 5번 제외) 반복해 평균을 냈습니다. 모든 알고리즘에 같은 방법과 같은 단위(ms)를 씁니다. 병합 정렬의 임시 배열 `malloc/free`도 알고리즘의 일부이므로 시간에 포함됩니다. 비교 횟수와 재귀 깊이를 세는 카운터는 모든 알고리즘에 똑같이 들어 있어 영향이 비슷합니다.

**메모리 사용량(추가 메모리):** 직접 계산하는 방식을 썼습니다. 원본 배열은 제외합니다.

- **추가 할당:** 병합 정렬은 임시 배열 `n × sizeof(int)` 바이트(4n)이고, 퀵 정렬은 0입니다(제자리 정렬).
- **재귀 호출 스택:** 실행 중 기록한 **최대 재귀 깊이** × **재귀 호출 1회당 프레임 크기**로 계산합니다. 프레임 크기는 매개변수 + 지역변수 + 반환 주소·이전 프레임 포인터(포인터 크기의 2배)를 더해 16바이트 단위로 올림한 값이며, 64비트 빌드에서 병합·퀵 모두 48바이트입니다(프로그램이 `sizeof`로 계산해 첫 줄에 출력).
- **제외한 것:** 재귀 함수가 아닌 보조 함수(`partition`, `merge_arrays` 등)가 최대 깊이에서 잠깐 쓰는 프레임은 크기가 작고 두 알고리즘에 비슷하게 있으므로 제외했습니다. 컴파일러 최적화에 따라 실제 프레임 크기는 다를 수 있어서, 이 값은 측정이 아니라 계산한 추정값입니다.
- **예시:** n=20,000 병합 정렬 = 80,000(임시 배열) + 16(최대 깊이) × 48 = 80,768바이트.

## 3. 분석

### 비교 횟수
- **병합 정렬이 가장 적습니다.** n=20,000에서 병합은 약 26.1만 회로, 퀵 정렬 평균(First 33.9만, Median3 31.9만)보다 18~23% 적습니다. 모든 크기에서 같은 경향입니다.
- **원인:** 병합 정렬은 항상 배열을 정확히 반으로 나눕니다. 그래서 단계가 log₂n 단계로 고정되고, 각 단계에서 비교는 많아야 n번이며 한쪽이 먼저 소진되면 비교 없이 나머지를 복사하므로 약 n log₂n − 1.25n회입니다(n=20,000에서 이론값 약 260,750, 측정 평균 260,913). 반면 퀵 정렬은 피벗이 구간을 반으로 나누지 못하는 경우가 있어 평균 약 1.39 n log₂n 회가 되고(2(n+1)H_n − 4n과 일치), 분할마다 모든 원소를 피벗과 비교해야 합니다.
- **크기 증가:** 두 알고리즘 모두 n이 2배가 되면 비교 횟수가 2배보다 약간 더 늘어납니다(n log n 증가). 병합은 n=1,000의 8,703회에서 n=16,000의 203,274회로 약 23배(n은 16배), 퀵(First)은 10,280회에서 264,999회로 약 26배입니다. 병합은 항상 n log n이지만 퀵은 피벗 운에 따라 변동이 있어 크기별 값이 들쭉날쭉합니다.

### 실행시간
- **이 실험에서는 비교 횟수가 더 많은 퀵 정렬이 더 빨랐습니다.** n=20,000에서 퀵(First) 1.2240ms, 퀵(Median3) 1.2808ms, 퀵(Random) 1.3255ms, 병합 1.5652ms로, 병합이 퀵보다 약 18~28% 느렸습니다(모든 크기에서 같은 순서).
- **원인:** 정렬 시간은 비교 횟수만이 아니라 데이터 이동·메모리 접근 비용도 좌우합니다. 병합 정렬은 모든 단계에서 원소를 임시 배열로 옮겼다가 다시 원래 배열로 복사하므로 약 2 n log n번의 쓰기가 필요하고, 임시 배열 할당/해제 시간도 듭니다. 퀵 정렬은 제자리에서 교환만 하고 배열을 순차적으로 훑어 캐시 효율이 좋습니다. 정수 비교는 매우 싸기 때문에 비교 횟수 차이(약 20%)보다 이동 비용 차이가 시간에 더 크게 반영됐습니다.
- **크기 증가:** 두 알고리즘 모두 n이 2배가 될 때 시간이 약 2.1~2.6배로 늘어나 n log n 증가와 맞습니다(예: 병합 16,000→20,000에서 1.2419→1.5652ms, 약 1.26배로 n의 1.25배와 비슷).

### 메모리 사용량
- 병합 정렬은 n=20,000에서 80,768바이트로, 퀵 정렬(약 1.2~1.8KB)의 약 45~65배입니다. 병합의 메모리는 n에 비례해 늘어나지만(4,528 → 8,576 → 16,624 → ... → 80,768로 n이 2배면 약 2배) 퀵은 거의 변하지 않습니다.
- **원인:** 병합 정렬은 병합을 위해 n개짜리 임시 배열이 필요하고(4n바이트), 재귀 깊이는 log n(n=20,000에서 16)이라 스택은 768바이트뿐입니다. 퀵 정렬은 제자리 정렬이라 추가 배열이 없고 재귀 스택만 쓰며, 분할이 균형 잡힐수록 깊이가 얕아집니다(n=20,000에서 Median3 평균 약 26단계, First·Random 약 33~34단계).

### 퀵 정렬의 피벗 선택에 따른 차이
- **비교 횟수:** 100개 평균에서 Median3이 가장 적고(319,084), First(338,593)와 Random(340,238)은 거의 같습니다. 세 값의 중앙값이 극단값일 확률이 낮아 분할이 더 균형 있게 나뉘기 때문입니다. 단일 실험(1회)에서는 운에 따라 순위가 바뀌기도 했습니다(n=8,000은 Random이 최소, n=20,000은 Random이 최대).
- **메모리:** 균형 있게 나눌수록 재귀 깊이가 줄어서 Median3의 스택 사용량이 가장 적었습니다(n=20,000 평균 1,235바이트 vs 약 1,630바이트).
- **실행시간:** 비교 횟수는 Median3이 가장 적지만 시간은 First가 가장 짧았습니다(n=20,000에서 1.2240 vs 1.2808ms). 중앙값을 정하는 추가 비교와 분기 비용이 분할 개선 이득을 상쇄했고, Random은 난수 생성 비용(64비트 나머지 연산)이 분할마다 들어 가장 느렸습니다. 다만 이 시간 비교는 데이터 하나에 대한 결과이고 차이가 5% 안팎이라 환경에 따라 뒤집힐 수 있습니다. 무작위 데이터에서는 First도 문제가 없지만, 정렬된 입력에서는 First가 O(n²)이 된다는 점은 과제 12에서 확인했습니다.

### 시간·공간 복잡도 비교

| 항목 | 병합 정렬 | 퀵 정렬 |
|---|---|---|
| 시간(최선/평균) | O(n log n) | O(n log n) |
| 시간(최악) | O(n log n) | O(n²) (분할이 한쪽으로 치우칠 때) |
| 공간 | O(n) 임시 배열 + O(log n) 스택 | 제자리, O(log n) 스택(최악 O(n)) |
| 안정성 | 안정 | 불안정 |

실험은 이 표와 일치합니다. 병합은 어떤 입력에서도 같은 단계 수를 거치므로 비교 횟수가 일정하고(측정 평균 안정적) 대신 n에 비례하는 추가 메모리가 필요했습니다. 퀵은 비교가 약간 더 많지만 추가 메모리가 거의 없고 이동이 적어 실제 속도가 빨랐습니다.

### 결론
비교 횟수는 병합 정렬이 가장 적고, 실행시간은 퀵 정렬이 가장 빠르며, 메모리는 퀵 정렬이 압도적으로 적었습니다. 메모리가 충분하고 최악의 경우에도 성능이 보장되어야 하거나 안정 정렬이 필요하면 병합 정렬이, 메모리가 제한되고 평균 속도가 중요하면 Median-of-Three 피벗의 퀵 정렬이 적합합니다.
